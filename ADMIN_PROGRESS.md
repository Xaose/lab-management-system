# Прогресс разработки - Админка

## ✅ Что готово (Backend)

### API для управления пользователями
- `GET /api/users` - список пользователей с фильтрацией по роли, статусу, поиску
- `GET /api/users/:id` - получить пользователя
- `POST /api/users` - создать пользователя (с профилем студента/преподавателя)
- `PUT /api/users/:id` - обновить пользователя
- `DELETE /api/users/:id` - заблокировать/удалить пользователя

### API для управления группами
- `GET /api/groups` - список групп с фильтрацией
- `GET /api/groups/:id` - получить группу со студентами и дисциплинами
- `POST /api/groups` - создать группу
- `PUT /api/groups/:id` - обновить группу
- `DELETE /api/groups/:id` - удалить группу (только если нет студентов)
- `POST /api/groups/:id/students` - назначить студентов в группу

### API для управления дисциплинами
- `GET /api/disciplines` - список дисциплин с фильтрацией
- `GET /api/disciplines/:id` - получить дисциплину
- `POST /api/disciplines` - создать дисциплину (только преподаватели)
- `PUT /api/disciplines/:id` - обновить дисциплину
- `DELETE /api/disciplines/:id` - удалить дисциплину
- `POST /api/disciplines/:id/teachers` - назначить преподавателей
- `DELETE /api/disciplines/:disciplineId/teachers/:teacherId` - удалить преподавателя
- `POST /api/disciplines/:id/groups` - назначить группы
- `DELETE /api/disciplines/:disciplineId/groups/:groupId` - удалить группу

## ✅ Что готово (Frontend)

### Страницы админки
- `/admin/dashboard` - главная панель администратора с меню
- `/admin/users` - управление пользователями (таблица с фильтрами)
- `/admin/groups` - управление группами (карточки групп)
- `/admin/disciplines` - управление дисциплинами (список с фильтрами)

### Функционал
- Фильтрация по различным параметрам
- Поиск пользователей и дисциплин
- Создание групп через модальное окно
- Удаление/блокировка сущностей
- Отображение статистики (счетчики)

## 🚀 Запуск проекта

### 1. Запустить Docker Desktop
Убедитесь, что Docker Desktop запущен и работает.

### 2. Запустить PostgreSQL
```bash
docker compose up -d postgres
```

### 3. Применить миграции
```bash
npm run db:migrate
```
Когда спросит название миграции, введите: `init`

### 4. Заполнить базу тестовыми данными
```bash
npm run db:seed --workspace=packages/database
```

### 5. Запустить приложение
```bash
npm run dev
```

### 6. Открыть в браузере
- Frontend: http://localhost:3000
- Backend API: http://localhost:4000
- Health check: http://localhost:4000/health

### Валидация
Все API эндпоинты используют Zod для валидации входных данных.

### Авторизация
- Все роуты `/api/users`, `/api/groups` требуют роли ADMIN
- Роуты `/api/disciplines` доступны преподавателям и админам
- JWT токен передается в header `Authorization: Bearer <token>`

### База данных
- PostgreSQL 16
- Prisma ORM
- Полная схема с 12 таблицами и всеми связями

## 🎯 Цель проекта

Создать полноценную LMS систему по аналогии с MyStat (ItStep), lms.bsuir:
- **Админ** - управляет системой, выдает права преподавателям
- **Преподаватель** - создает дисциплины и лабы, проверяет работы
- **Студент** - просматривает лабы, загружает решения, получает оценки
