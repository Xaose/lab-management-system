## 🔐 Как работает защита:

### Middleware (server-side):
```
Пользователь → Запрос → Middleware → Проверка токена → Разрешить/Редирект
```

**Проверяет:**
1. Есть ли токен в cookies?
2. Публичный ли маршрут?
3. Авторизован ли пользователь?
4. Соответствует ли роль маршруту?

**Редиректы:**
- `/student/*` без авторизации → `/auth/login?redirect=/student/*`
- `/teacher/*` как STUDENT → `/unauthorized`
- `/auth/login` будучи авторизованным → соответствующий dashboard

### ProtectedRoute (client-side):
```tsx
<ProtectedRoute allowedRoles={['TEACHER', 'ADMIN']}>
  <AdminPanel />
</ProtectedRoute>
```

Используется для дополнительной защиты на уровне компонентов.

## 🚀 Использование:

### Автоматическая защита (middleware):
Все маршруты `/student/*`, `/teacher/*`, `/admin/*` автоматически защищены. Ничего дополнительно делать не нужно.

### Ручная защита компонента:
```tsx
import { ProtectedRoute } from '@/components/ProtectedRoute'

export default function TeacherPage() {
  return (
    <ProtectedRoute allowedRoles={['TEACHER']}>
      <div>Контент только для преподавателей</div>
    </ProtectedRoute>
  )
}
```

### Navbar:
Уже добавлен в `layout.tsx` — показывается автоматически на всех страницах кроме `/` и `/auth/*`.
